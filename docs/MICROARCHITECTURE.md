# Микроархитектура MT16

## Barrel multithreading

MT16 имеет один общий тракт данных и четыре полностью аппаратных контекста. В
каждом контексте находятся `PC`, `ACC`, `IR`, `OPERAND`, `STATE`, `ZERO` и
`HALT`. Двухбитный round-robin счётчик выбирает следующий контекст на каждом
положительном фронте такта:

| Такт | Активный поток | Микрошаг типичной команды |
|---:|---:|---|
| 0 | T0 | fetch opcode |
| 1 | T1 | fetch opcode |
| 2 | T2 | fetch opcode |
| 3 | T3 | fetch opcode |
| 4 | T0 | fetch operand |
| 5 | T1 | fetch operand |
| 6 | T2 | fetch operand |
| 7 | T3 | fetch operand |
| 8 | T0 | execute |

Таким образом, латентность команды одного потока — 12 глобальных тактов, но при
четырёх активных потоках ядро завершает до одной команды каждые три такта. Это
fine-grained multithreading, а не программное переключение задач: контексты не
сохраняются в RAM и не требуют кода операционной системы.

Остановленный поток продолжает занимать свой слот, но не меняет состояние. Это
делает расписание детерминированным и значительно упрощает потактовую проверку.

## Микропрограмма

Все команды проходят три состояния:

1. `FETCH_OPCODE`: `IR ← ROM[PC]`, `PC ← PC + 1`.
2. `FETCH_OPERAND`: `OPERAND ← ROM[PC]`, `PC ← PC + 1`.
3. `EXECUTE`: управляющая ROM декодирует младшие четыре бита `IR` и разрешает
   нужные записи. Затем `STATE ← FETCH_OPCODE`.

Управляющее слово имеет 32 бита; используются младшие 13:

| Биты | Поле | Назначение |
|---:|---|---|
| `2:0` | `ACC_SOURCE` | hold, immediate, memory, ALU или old memory |
| `6:3` | `ALU_OP` | pass, add, sub, and, or, xor, not, shl, shr |
| `7` | `WRITE_ACC` | запись `ACC` и `ZERO` |
| `8` | `WRITE_MEMORY` | запись общей RAM |
| `9` | `WRITE_PC` | запрос перехода |
| `10` | `CONDITIONAL_ZERO` | переход разрешён только при `ZERO=1` |
| `11` | `ATOMIC` | в RAM пишется `MEM + ACC`, в ACC — старое `MEM` |
| `12` | `HALT` | защёлкивание остановки текущего контекста |
| `31:13` | — | зарезервированы, равны нулю |

Файл [`mt16/core.py`](../mt16/core.py) — единый источник определения таблицы
микрокоманд для эталонной модели, генератора control ROM и тестов.

## Общая память и атомарность

RAM асинхронно читается и синхронно записывается. Адрес берётся из `OPERAND`
активного контекста. При обычном `ST` на вход данных поступает `ACC`.

`ATOMADD` выполняет read-modify-write в одном неделимом `EXECUTE`-микрошаге:
старое значение RAM одновременно возвращается в аккумулятор, а сумма старого
значения с `ACC` фиксируется на фронте такта. До следующего потока планировщик
доходит только после этого фронта, поэтому потерянное обновление невозможно.

## Сброс и наблюдение

`Reset` обнуляет планировщик и все регистры контекстов. ROM неизменяемы, RAM
сбрасывается в ноль. Для ручной отладки наружу выведены текущие `TID`, `PC`,
`ACC`, `IR`, `OPERAND`, `STATE`, `CurrentHalt`, общий `AllHalted`, четыре
результирующих порта и `ATOMIC_COUNT`.

## Воспроизводимая схема

`hardware/generate.py` собирает пять схем одного проекта:

- `ALU16` — отдельно тестируемый тракт ALU;
- `MicrocodeControl` — управляющая ROM;
- `Scheduler4` — round-robin планировщик;
- `MT16_Core` — проверенное вычислительное ядро с компактным условным обозначением;
- `MT16_Computer` — интегрированный компьютер.

На главной схеме четыре программных ROM и общая RAM вынесены из символа ядра и
соединены с ним настоящими линиями. Это не декоративная копия: именно по этим
видимым шинам идут адреса `PC`, байты команд, адрес RAM, данные и разрешение
записи. Внутренний `AUTO CLOCK` позволяет запустить уже прошитую демонстрацию
одной стандартной кнопкой `Ticks Enabled`.

Генератор сначала выполняет демонстрацию в потактовой Python-модели, затем
встраивает те же ROM в `.circ` и строит последовательный тест-вектор с ожидаемым
финальным состоянием. Поэтому расхождение между ISA, ROM, микрокодом и схемой
обнаруживается интеграционным тестом Logisim.
